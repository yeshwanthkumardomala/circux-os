## Where the Circux admin token is stored

There are two separate credential systems:

1. **Local relay administrator token — `CIRCUX_ADMIN_TOKEN`**
   - This is generated or configured on the computer running the local Circux relay/FastAPI services.
   - On Windows, run `RUN-CIRCUX.bat`. If the token is missing, the launcher creates one, saves it in the repository-root `.env` file, and prints it in the launch terminal.
   - If already configured, read the existing `CIRCUX_ADMIN_TOKEN` value from the repository-root `.env` file on that same machine.
   - In the Circux admin workspace, open Settings → Local backend access, paste the token, and save it. It is stored in that browser's local storage for local Board Health/relay access.
   - The frontend cannot read the computer's `.env` file directly. The token is not stored in Supabase or Vercel environment variables and must not be committed to Git.

2. **Circux cloud administrator account**
   - This is a Supabase Auth account with the `admin` role in `public.profiles`.
   - Sign in at https://circux-os.vercel.app/ using the provisioned account for the current Supabase project.
   - The cloud admin login is not the same as `CIRCUX_ADMIN_TOKEN`. Do not paste a Supabase access token into the local relay-token field.

Never publish either credential in README files, screenshots, chat, QR codes, or client-side public environment variables. If the local token is lost, rotate it on the host machine by updating `CIRCUX_ADMIN_TOKEN` in `.env` (or remove the entry and restart the Windows launcher to generate a new token), then update the browser's saved value.
